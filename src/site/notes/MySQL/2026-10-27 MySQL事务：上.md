设置默认隔离级别为未提交
```SQL
set global transaction isolation level READ UNCOMMITTED;
```

创建测试表：
```SQL
create table if not exists account( 
	id int primary key, 
	name varchar(50) not null default '', 
	blance decimal(10,2) not null default 0.0 
)ENGINE=InnoDB DEFAULT CHARSET=UTF8;
```
确认当前事务的提交方式：
```SQL
show variables like 'autocommit';
```

启动事务--二选一即可：
```SQL
start transaction;
begin;
```
插入数据：
```SQL
insert into account values(1,'张三',1234.5);
```
设置保存点：
```SQL
savepoint s2;
```
上面的内容会被整理成一个事务，后面可以进行原子性操作
进行回滚操作：
```SQL
select * from account;
```

结束事件：
```SQL
commit;
```
回滚是不是必须设置回滚点？
没有保存点不能定向回滚，但是还是可以回滚的，也就是都没了。可以对这个事务所做的所有事务都放弃掉。
如果你在修改的途中出现异常会自动回滚保证结果是可以预测的。
手动取事务和自动对事务进行操作是两回事都不会造成影响。
我们以前讲的单SQL语句也全部都是事务
之前都是自动提交的，所以我们感觉不到。
隔离级别测试：
1. 读未提交
2. 读提交
>不可重复读，任何一个有读取条件的事务极有可能出现这样的情况，就是读取同一个数据表得到的数据不一样

这样合理吗？   
不合理，事务不能被两个终端同时读，会出现不可重复读的情况。串行化隔离级别，这就意味着事务的执行要按照到来的顺序进行排队
